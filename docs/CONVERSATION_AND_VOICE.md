# 会話の履歴と声

2026-11-06実装。本家キャラチャットの機能差分のうち、履歴、声の選択・固定、本文とTTSの対応を扱う。

## 使い方

- **履歴**: 会話・キャラ・作業フォルダから絞り込み、過去の会話を開く。保存時のworkspace・エンジン・モデル・プロフィール・声・ホームモードを復元する。選んだ会話の全文をMarkdownで書き出せる。
- 起動時は前回の保存済み会話を表示する。会話の過去のタスクを再実行する操作ではない。ホームモードの定期チェックは既存のホーム設定に従う。
- **声**: VoxCPM2 / Irodori / VoiceVoxを選択する。VoxCPM2とIrodoriは登録済みの参照音声を選んで試聴できる。ボイスデザインから3候補を作り、聴き比べて1つを登録・選択できる。「保存」で適用する。
- Irodoriは日本語用。声の特徴、参照音声、シード、速度を保存し、音声とAvatarの両方へ適用する。
- 回答の**当時の声で再生**は保存した声設定を使う。**現在の声で再生**は今の設定を使う。Textモードでも明示的な再生は可能。
- **音声停止**は再生予約済みの音、デコード中の音、予約済み映像、音声HTTP要求を停止する。会話切替・次の送信・出力モード変更でも古い音声を停止する。

登録済み音声が後から削除されている場合は、元の声の再現を保証できない。カタログから見つからないIDは勝手に別の声へ置き換えず、保存済みIDとして表示する。

## Irodoriの英語表記

本文は原文を保ち、音声の送信直前だけ読みを解決する。別のLLMで要約・翻訳した文章は作らない。

1. ユーザー辞書を優先する。例: `MyTool=マイツール`。大文字・小文字は区別しない。
2. 組み込み辞書でGitHub、Next.js、API、GPUなどをカナへ変換する。長い表記から照合し、通常の英単語の途中で部分一致させない。
3. 辞書にない英語表記はアルファベット読みへ変換する。自然な単語の読みを推測する機能ではないので、固有名詞には辞書の追加が有効。
4. **読みを確認**に実際に送る文章、置き換えの対応、綴り読みになった語を表示する。

この変換はIrodoriだけに適用し、設定で無効にできる。VoxCPM2の英文や表示・コピー・書き出しの原文は変更しない。全角英数字は音声用に半角へ正規化する。辞書は音声設定とともに保存し、発言の音声設定にも写しを残す。

## 応答と保存

DesktopのReActは、本家の`narration` / `speech`構造に、作業の詳細を置く`artifact`を加えた形式を要求する。

```json
{"version":1,"blocks":[
  {"type":"speech","speaker":"Eve","text":"修正しました。検証も通っています。","delivery":"穏やかに"},
  {"type":"artifact","text":"変更ファイル: /tmp/example.html"}
]}
```

同じブロックを画面表示・履歴・書き出し・TTSに使う。TTSはspeechだけを読み、Markdownの装飾を除去する。連続する同じ話者・演技の台詞はまとめる。音声変換後にAPI上限を超える場合は分割し、末尾を切り捨てない。

CLIのモデル再開用JSONLと、Desktopの表示用記録には異なる役割がある。

| 保存先 | 内容 |
| --- | --- |
| `~/.kotonia/sessions/<id>.jsonl` | 既存CLIのモデル文脈・ツール履歴。再開に使用 |
| `~/.kotonia/desktop/sessions/<id>.json` | 表示用会話、正規化した応答ブロック、メッセージID、発言時の音声設定、会話の設定 |
| WebViewのlocalStorage | 現在のプロフィール・声の好み、前回の保存済み会話ID等 |

表示用記録は一時ファイルからのrenameで更新する。Unixではファイルを0600で作成する。声設定を変更しても、過去メッセージの音声設定の写しは変更しない。保存失敗は画面に通知する。

既存JSONLはCLIの`load_session_transcript`で読み、ツール出力を会話本文として混ぜない。古い会話には当時のプロフィール・声がない場合があり、その場合は現在の設定を使うことを表示する。旧ログ全体の書き換えは行わない。続けて発言する際にDesktopの表示用記録へ取り込む。

旧VOICE/SPEAK形式では、SPEAKの文章を可視の台詞にし、元の詳細本文も表示する。Claude Code等の平文は互換処理でブロックへ変換し、コードフェンスを表示専用にする。これらの互換処理でも1000文字の切り捨ては行わない。

## 共通化の範囲

`speech.rs`が声・演技・Irodoriの読みを解決し、通常音声とDittoの送信形式を作る。`response.rs`が構造化応答と旧形式を正規化する。再生・保存・表示ごとに不可視の別回答を作らない。

既存の本家API（音声一覧、合成、候補生成・採用、アバター）を使用する。トークンはRust側に置く。WebのUI・音声ランタイムを今回Desktopへ移植・統合したわけではない。本家と互換の基本ブロック形と既存APIを土台にしている。

複数キャラ管理、共演者ごとの別音声、回答編集・再生成、生成途中からの読み上げは別の作業。新しい音声処理も最終回答の確定後に開始する。HTTP要求の中止が上流のGPU計算の停止まで伝わるかは、サーバー実装に依存する。

## 検証

```sh
npm test
cargo +1.94.1 test --manifest-path src-tauri/Cargo.toml
cargo +1.94.1 build --manifest-path src-tauri/Cargo.toml
```

ブラウザでの画面テストはPlaywrightを別途利用できる環境で実行する。Tauri IPCと音声デバイスをモックし、外部APIやGPUは呼ばない。

```sh
# 本家hageの開発環境を兄弟ディレクトリに置いている場合
KOTONIA_PLAYWRIGHT_MODULE=../hage/node_modules/@playwright/test npm run test:e2e
```

ChromiumとWebKitで履歴復元、即時イベント、書き出しの失敗・再試行、声選択・候補採用、読み確認、声の保存、音声とAvatarの設定、停止中のデコード、古いイベントの無視、390px幅を確認する。`KOTONIA_E2E_BROWSERS=chromium`で対象を限定できる。

実際の音色や発音の自然さは、接続した音声サーバーでの試聴が必要。
